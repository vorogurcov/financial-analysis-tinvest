# Задача 3. Корреляции доходностей и рыночные условия

Пункт 3 плана из `README.md`: анализ корреляционных связей между доходностями финансовых инструментов и их изменения в зависимости от рыночных условий.

Панель и рыночный ряд берутся из `plans/task_1.md` (`load_panel`, `equal_weight_market`). Второй индекс и второй способ усреднения рынка не вводятся.

## 1. Цель

Измерить линейную и ранговую связь дневных лог-доходностей включённых акций и показать, как средняя попарная связь соотносится с волатильностью равновзвешенного рынка.

Отдельно фиксируется разница средней связи внутри сектора и между секторами: сектор — характеристика инструмента из пункта 1, и корреляционная структура должна быть с ней сопоставима.

Оценки описывают совместную динамику на истории окна. Они не используются как сигнал к сделке.

## 2. Общие соглашения

Окружение этого пункта: зависимости ставим и запускаем через uv. Перед командами активируем виртуальное окружение: `.venv/scripts/activate`.

Действуют соглашения пункта 1: дневные лог-доходности после фильтра скачков, покрытие рыночного дня не меньше 80% включённых имён, результаты в том же каталоге прогона, CSV utf-8-sig, рисунки dpi 160, подписи по-русски.

Для регрессии с HAC-ошибками нужен `statsmodels`. Запуск — `python -m tinvest.research`, шаг после анализа объёма.

## 3. Границы

В матрицы входят только включённые тикеры панели. Пара тикеров попадает в расчёт, если у них не меньше 60 общих дат с непустыми `log_return` у обоих. Иначе пары в длинной таблице нет.

Окно скользящей корреляции — 63 торговых дня. Внутри окна тикер участвует, если у него не меньше 50 непустых доходностей. Если таких тикеров меньше 20, день не получает среднюю попарную корреляцию.

Режимы волатильности строятся по скользящим окнам, а не по отдельным дням: соседние дни делят 62 наблюдения из 63, и проверка «по дням как по независимой выборке» здесь не ставится. Формальный коэффициент — регрессия раздела 6 со стандартными ошибками Ньюи–Уэста, `maxlags = 63`.

Стрессовый срез — отдельное описание, не третья регрессия. День стресса: `market_return <= -0.02`. Срез публикуется, если таких дней не меньше 15. Иначе строка режима есть, числа пустые, `note = too_few_stress_days`.

## 4. Полная выборка

По всей панели:

- Пирсон и Спирмен по каждой допустимой паре. Диагональ в средние не входит.
- Средняя попарная корреляция — среднее верхнего треугольника матрицы Пирсона.
- Матрица для рисунка упорядочена по `sector`, внутри сектора по `ticker`. Подпись деления: `"{sector} | {ticker}"`, размер шрифта 6. Числа в ячейках не подписываются.

Секторный разрез использует `sector_group` из пункта 1:

- `within` — среднее Пирсона по парам, у которых `sector_group` совпадает и группа не равна `прочие`;
- `between` — среднее по парам с разными группами, обе группы не равны `прочие`.

Если внутрисекторных пар меньше 10, строка `within` пишется с `note = too_few_pairs`.

## 5. Окна и режимы

На каждую дату `t`, где хватает истории:

- `pair_corr_t` — средняя попарная корреляция Пирсона в окне из 63 дней, заканчивающемся в `t`, с порогами раздела 3;
- `market_rv_t` — `std(market_return, ddof=1) * sqrt(252)` по тем же 63 дням. Дни без `market_return` окно не разрывают молча: если в 63 календарных торговых датах панели непустых значений рынка меньше 63, день `t` пропускается.

Терцили `low_vol`, `mid_vol`, `high_vol` считаются по `market_rv_t` на всём наборе окон, где обе величины непусты. Границы — эмпирические квантили 1/3 и 2/3. Строка режима содержит число окон, среднее `pair_corr_t` и среднее `market_rv_t`.

Стрессовая корреляция — одна матрица Пирсона, посчитанная только по датам с `market_return <= -0.02` (те же пороги пар: 60 общих точек, здесь это число стрессовых дней с совместными наблюдениями). В таблицу режимов она кладётся одной строкой `stress` со столбцом `n_days`.

Терцили делят историю на три корзины для рисунка. Они используют квантили всей выборки окон, поэтому это способ показать наклон, уже оцененный регрессией, а не отдельный эксперимент с заранее заданным порогом.

## 6. Регрессия

Одна регрессия на наборе дней, где определены обе величины:

```text
pair_corr_t = a + b * market_rv_t + e_t
```

Ковариация HAC (Ньюи–Уэст), `maxlags = 63`. В CSV одна строка на параметр (`Intercept`, `market_rv`) с `coef`, `std_err`, `p_value`, `n`, `r_squared`. p-value двусторонние.

Если таких дней меньше 100, файл регрессии содержит строку с пустыми коэффициентами и `note = too_few_windows`, рисунок режимов при этом строится только при наличии хотя бы одного окна.

Независимый рыночный ряд (другой источник индекса) в класс не передаётся.

## 9. Проверки без сети

Файл `tests/test_task3_correlation.py`, `seed = 0`.

- Два блока дат. В первом блоке доходности тикеров равны общему фактору плюс слабый шум, во втором — независимые ряды. Средняя попарная корреляция первого блока выше, чем второго.
- День с `market_return = -0.03` помечается стрессовым, день с `market_return = -0.01` нет.
- Пара с 59 общими точками отсутствует в `task3_pairs.csv`, пара с 60 точками присутствует.
- Окно, в котором рыночный ряд короче 63 наблюдений, не получает `market_rv`.
- Коэффициент регрессии на ряде, где `pair_corr` линейно растёт вместе с `market_rv` без шума, положительный.

## 10. Критерии приёмки

- В том же каталоге прогона появляются таблицы пар, окон, режимов, секторного среза и регрессии плюс три рисунка.
- Каждая строка `task3_pairs.csv` имеет `n_overlap >= 60`, `ticker_a < ticker_b` в лексикографическом порядке, и диагональных пар нет.
- В `task3_regimes.csv` есть `low_vol`, `mid_vol`, `high_vol`. Строка `stress` есть всегда; при малом числе дней у неё заполнен `note`.
- Регрессия использует HAC с `maxlags = 63`. В файле коэффициентов это видно колонкой `cov = HAC_63`.
- Сводка в логе содержит полную среднюю попарную корреляцию, `b` и средние `pair_corr` нижнего и верхнего терциля.
- При числе окон меньше 100 регрессия не выдаёт коэффициент и не подменяет его оценкой с другими ошибками.

## 11. Связь с другими пунктами

`market_return` — только ряд `equal_weight_market`. Пункт 5 использует тот же ряд для признака `market_rv_21`, но окно признака там 21 день и считается иначе, чем `market_rv` этого пункта (63 дня). Оба определения остаются каждый в своём пункте, с разными именами колонок, чтобы 21-дневный признак модели не перепутать с 63-дневным режимом.
