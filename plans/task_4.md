# Задача 4. Временные закономерности и гипотезы

Пункт 4 плана из `README.md`: исследование временных закономерностей финансовых показателей и проверка статистических гипотез о наличии автокорреляции и устойчивости волатильности.

Вход — `PanelFrame` из `plans/task_1.md`. Определения `log_return` и годовой волатильности те же.

## 1. Цель

Проверить на каждой включённой акции фиксированный набор гипотез и свести доли отклонений с поправкой на число тикеров.

Гипотезы задаются до расчёта, двусторонние там, где критерий двусторонний, и не заменяются по результатам прогона.

| Код | H0 | Статистика |
| --- | --- | --- |
| `lb_return` | У дневных лог-доходностей нет автокорреляции на лагах 1…10 | Льюнг–Бокс, lag = 10 |
| `lb_square` | У квадратов лог-доходностей нет автокорреляции на лагах 1…10 | Льюнг–Бокс, lag = 10 |
| `arch_lm` | Нет ARCH-эффекта на 5 лагах | `statsmodels.stats.diagnostic.het_arch`, `nlags = 5` |
| `weekday` | Распределение `\|r\|` не зависит от дня недели | Краскел–Уоллис по группам Пн…Пт |
| `rv_persist` | Коэффициент AR(1) у 21-дневной реализованной волатильности равен нулю | МНК `rv_21_t` на `rv_21_{t-1}`, HAC, `maxlags = 21` |

Устойчивость волатильности читается по `lb_square`, `arch_lm` и знаку коэффициента `rv_persist`. Автокорреляция самих доходностей — отдельная строка `lb_return`: она описывает временную структуру средней, а не дисперсии.

## 2. Общие соглашения

Окружение этого пункта: зависимости ставим и запускаем через uv. Перед командами активируем виртуальное окружение: `.venv/scripts/activate`.

Действуют соглашения пункта 1. Нужны `scipy` и `statsmodels`. Запуск — `python -m tinvest.research`, шаг после корреляций.

День недели — день календаря `Europe/Moscow` у метки `time`. Суббота и воскресенье в критерии `weekday` не участвуют. Если после этого у тикера меньше двух разных дней недели с наблюдениями, `weekday` для него не считается (`note = too_few_weekdays`).

Тикер входит в семейство тестов, если непустых `log_return` не меньше 200. Иначе строка в `task4_tests.csv` всё же есть, статистики пустые, `note = too_few_returns`. Такой тикер не участвует в поправке Холма.

Если тикеров с посчитанным тестом в семействе меньше 15, поправка Холма для семейства не делается, в сводке `note = too_few_tickers`. Сами статистики по тикерам сохраняются.

## 3. Ряды

Внутри тикера, по возрастанию `time`:

- `r_t` — `log_return` без пустых значений, временной порядок сохранён. Разрыв календаря ряд не интерполирует: следующая имеющаяся доходность становится следующим наблюдением теста. Это согласовано с тем, что пропущенный день не получает синтетическую доходность.
- `r_t²` — квадрат того же ряда, для `lb_square`.
- `rv_21_t` — `std` последних 21 лог-доходностей, включая `t`, `ddof = 1`, умноженный на `sqrt(252)`. Окно с пропуском внутри 21 точек не заполняется: если в 21 предшествующих позициях ряда (после удаления NaN это просто 21 последних наблюдений) не хватает 21 точек, значение пустое. Лаг AR(1) — предыдущее наблюдение `rv_21` в этом ряде.

Льюнг–Бокс и ARCH-LM считаются по `r_t` после удаления NaN, без добивания нулями.

Для `rv_persist` в оценку входят строки, где заданы и `rv_21_t`, и `rv_21_{t-1}`. Стандартные ошибки HAC с `maxlags = 21`, потому что соседние окна `rv_21` делят 20 дней. p-value двусторонний. Дополнительно пишется `phi` (оценка коэффициента) и `half_life`:

```text
half_life = ln(0.5) / ln(phi)    при 0 < phi < 1
```

Иначе `half_life` пустой. При `phi <= 0` или `phi >= 1` период полужизни этой формулой не определяется, и пустая ячейка остаётся пустой без подстановки большого числа.

## 4. Поправка на множество тикеров

Внутри каждого кода гипотезы p-value тикеров с посчитанным тестом корректируются методом Холма. Уровень отклонения — 0,05 по скорректированному p-value.

Сырой и скорректированный p-value хранятся в разных колонках. Доля отклонений в сводке считается только по скорректированному p-value.

Для `rv_persist` в сводку дополнительно входит доля тикеров, у которых скорректированный p-value < 0,05 и `phi > 0`. Отклонение H0 при отрицательном `phi` в эту долю не входит: оно не подтверждает устойчивость волатильности.

## 5. Что пишется в сводку

`HypothesisSummary` по каждому коду гипотезы:

- число тикеров с тестом;
- медиана сырого p-value;
- доля отклонений после Холма;
- для `rv_persist` ещё медиана `phi`, медиана `half_life` по тикерам с `0 < phi < 1`, доля устойчивых (`phi > 0` и отклонение H0).

Текстовый шаблон лога фиксирован: для каждого кода одна строка `code, n, median_p, reject_share`. Отдельного порога «эффект есть, если доля выше X» в коде нет. Доля сама является результатом.

## 8. Проверки без сети

Файл `tests/test_task4_hypotheses.py`. Оба ряда длины 500, `seed = 0`.

- Независимый ряд `N(0, 1)`. p-value `lb_return` и `arch_lm` выше 0,05.
- Ряд с кластеризацией: `x_t = 0.9 * x_{t-1} + e_t`, `e_t ~ N(0, 1)`, `r_t = z_t * exp(0.5 * x_t)`, `z_t ~ N(0, 1)` независим от `e_t`. p-value `arch_lm` ниже 0,01.
- `half_life` при `phi = 0.5` равен `ln(0.5) / ln(0.5) = 1`. При `phi = 0` и при `phi = 1.1` ячейка пустая.
- Пять одинаковых сырых p-value `0.01` после Холма дают невозрастающую последовательность скорректированных значений, и минимальный скорректированный p-value не меньше сырого.
- Субботняя метка не попадает в группы Краскела–Уоллиса.

Эталон `phi = 0.5` проверяется отдельной функцией периода полужизни, без подгонки регрессии.

## 9. Критерии приёмки

- `task4_tests.csv` содержит пять кодов гипотез на каждый включённый тикер.
- Там, где тест посчитан, есть сырой p-value. `p_holm` заполнен, когда в семействе не меньше 15 тикеров с тестом.
- `half_life` заполнен только при `0 < phi < 1`.
- В `task4_summary.csv` пять строк, доли отклонений лежат в `[0, 1]`.
- Три рисунка лежат в `figures/` и подписаны по-русски.
- Лог содержит пять строк шаблона из раздела 5.
- Модульные проверки раздела 8 проходят на фиксированном `seed`.

## 10. Связь с другими пунктами

Пункт 5 прогнозирует повышенную волатильность и может опереться на вывод этого пункта в тексте отчёта, но не ветвится по p-value: модель пункта 5 оценивается при выполнении его собственного порога по объёму данных, независимо от доли отклонений `arch_lm`. Окно `rv_21` совпадает по длине с признаком `rv_21` пункта 5; формула `std(ddof=1) * sqrt(252)` одна и та же.
