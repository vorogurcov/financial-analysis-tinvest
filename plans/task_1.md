# Задача 1. Распределение доходностей и волатильности

Пункт 1 плана из `README.md`: анализ распределения доходностей и волатильности российских финансовых инструментов и их зависимости от характеристик инструментов.

Задача задаёт общую выборку и контракт панели. Пункты 2–5 читают эти данные и не вводят второе определение доходности, оборота или рыночного ряда.

## 1. Цель

Описать, как устроены дневные лог-доходности и годовая волатильность акций Московской биржи, и измерить связь этих величин с характеристиками выпуска: сектор, тип акции, размер выпуска, типичный оборот, лот, возраст с IPO, признаки дивиденда, ликвидности и шорта.

Результат пункта — таблицы метрик, ранговые корреляции, групповое сравнение секторов, регрессия волатильности и четыре рисунка.

## 2. Общие соглашения

- Python 3.12. Зависимости ставим и запускаем через uv. Перед командами этого пункта активируем виртуальное окружение: `.venv/scripts/activate`. Новые пакеты добавляются в `pyproject.toml` через uv. Для этого пункта нужны `scipy` и `statsmodels`.
- Токен берётся из `.env` (`TINVEST_TOKEN`) и не записывается в таблицы, логи и рисунки.
- Метки свечей хранятся в UTC. Календарь «сегодня» и подписи осей дат — `Europe/Moscow`.
- Интервал свечей — `CandleInterval.CANDLE_INTERVAL_DAY`.
- Сырые свечи лежат в `data/processed/<TICKER>/candles.parquet` и `candles.csv` (utf-8-sig), как уже делает `tinvest.storage`.
- Каталог выборки — `data/processed/universe.parquet`.
- Каталог прогона — `src/tinvest/results/DD_MM_YYYY_HH_MM/`. CSV результатов — utf-8-sig, без индекса. Рисунки — в `figures/`, dpi 160, как у `Analysis._save`.
- Имена колонок и модулей — английские `snake_case`. Подписи графиков — русские.
- Схема таблицы — подкласс `TypedFrame`, сборка через `build`. Сценарий расчёта — подкласс `Analysis`: `prepare`, затем `analyze`, затем `plot`, сводка — отдельный dataclass.
- Исследование запускается командой `python -m tinvest.research`.
- Сбой одного тикера при загрузке не останавливает сбор: три повтора с паузой 1 с, 2 с и 4 с, затем строка в `data/processed/fetch_errors.csv` (`ticker`, `figi`, `error`) и переход к следующему тикеру. Между инструментами пауза 0,2 с.
- Закрытия не корректируются на дивиденды и сплиты. Защита от сплита задана ниже отдельным правилом и одинакова для всех пунктов плана.

## 3. Границы

В выборку входят акции режима `TQBR`:

- `instrument_status` = `INSTRUMENT_STATUS_BASE`;
- `class_code` = `TQBR`;
- `currency` = `rub`;
- `country_of_risk` = `RU`;
- `share_type` — `SHARE_TYPE_COMMON` или `SHARE_TYPE_PREFERRED`;
- `otc_flag` = false, `blocked_tca_flag` = false, `for_qual_investor_flag` = false;
- `api_trade_available_flag`, `buy_available_flag` и `sell_available_flag` = true;
- `issue_size` > 0.

Список берётся методом `client.instruments.shares`, а не `find_instrument` (в используемой версии клиента поиск помечен устаревшим).

Облигации, фьючерсы и фонды в этот пункт не входят. У облигации в свече нет купона, у фьючерса ряд рвётся на экспирации, фонд повторяет корзину тех же акций и размывает связь «характеристика выпуска → волатильность».

После загрузки инструмент остаётся кандидатом, если в окне не меньше `min_bars` валидных закрытий (по умолчанию 252) и медианный рублёвый оборот положительный. Если кандидатов больше `max_names` (по умолчанию 80), остаются 80 с наибольшим медианным оборотом. Остальные пишутся в каталог с `included = false` и заполненным `exclude_reason`.

## 4. Параметры

`ResearchConfig` (frozen dataclass) в `tinvest.research.config`:

| Поле | По умолчанию | Смысл |
| --- | --- | --- |
| `lookback_days` | 1095 | Длина окна загрузки в календарных днях |
| `min_bars` | 252 | Минимум валидных дневных закрытий |
| `max_names` | 80 | Потолок включённых тикеров |
| `return_jump` | 0.5 | Порог простой доходности, выше которого доходность обнуляется |
| `refresh` | false | При `false` готовый parquet свечей не скачивается заново |
| `output` | каталог с меткой времени | Куда писать результаты |

`lookback_days` читается из `TINVEST_RESEARCH_LOOKBACK_DAYS`. `max_names` можно переопределить через `TINVEST_RESEARCH_MAX_NAMES`.

Окно загрузки: `end = now()`, `start = end - lookback_days`. В расчёт не входит свеча, у которой календарная дата в `Europe/Moscow` совпадает с сегодняшним днём в этой зоне.

## 5. Контракт данных

### 5.1. Каталог `universe.parquet`

Колонки `UniverseFrame`:

| Колонка | Тип | Правило |
| --- | --- | --- |
| `ticker`, `figi`, `name` | str | Как в карточке акции |
| `class_code`, `currency`, `country_of_risk` | str | После фильтра это `TQBR`, `rub`, `RU` |
| `lot` | int | Размер лота |
| `sector` | str | Пустой сектор API записывается как `не указан` |
| `share_type` | str | `common` или `preferred` |
| `issue_size` | int | Штук в выпуске |
| `nominal` | float | `float(quotation_to_decimal(share.nominal))` |
| `div_yield_flag`, `liquidity_flag`, `short_enabled_flag` | bool | Флаги карточки. `div_yield_flag` — признак наличия дивиденда, не ставка |
| `ipo_date` | datetime | UTC |
| `included` | bool | Инструмент вошёл в расчётную выборку |
| `exclude_reason` | str | Пустая строка, если `included`; иначе код причины |

Коды `exclude_reason`: `filter`, `fetch_error`, `too_few_bars`, `zero_turnover`, `over_cap`.

`FetchConfig` дополняется необязательным полем `figi: str | None = None`. Если `figi` задан, `fetch_candles` вызывает `get_all_candles` сразу с этим идентификатором и не вызывает `find_instrument`. Однотикерный путь без `figi` не меняется.

Повторный запуск с `refresh = false` пропускает скачивание, если `candles.parquet` уже есть. Смена `lookback_days` при `refresh = false` не удлиняет историю: для расширения окна нужен `refresh = true`. Это пишется в лог одной строкой при старте.

### 5.2. Панель

`load_panel(root) -> PanelFrame` в `tinvest.research.panel` собирает включённые тикеры в длинную таблицу. На диск панель не пишется.

Колонки: `ticker` (str), `time` (datetime, UTC), `open`, `high`, `low`, `close` (float), `volume` (int, лоты), `lot` (int), `sector` (str), `share_type` (str), `log_return` (float, NaN допустим).

Порядок очистки по каждому тикеру:

1. Выбросить бар, если `close <= 0`, `high <= 0`, `low <= 0` или `high < low`.
2. Выбросить сегодняшний незакрытый день по правилу из раздела 4.
3. Отсортировать по `time`, удалить повтор `time`, оставив последнюю строку.
4. `log_return = ln(close_t / close_{t-1})`.
5. Если простая доходность `close_t / close_{t-1} - 1` лежит вне `[-0.5, 0.5]`, записать бар в `data/processed/dropped_returns.csv` (`ticker`, `time`, `close_prev`, `close`, `simple_return`, `reason = abs_simple_return_gt_0.5`) и поставить `log_return` в NaN. Сами цены в панели остаются.

Рублёвый оборот бара: `volume * lot * close`. Объём свечи API — число лотов.

### 5.3. Рыночный ряд

`equal_weight_market(panel) -> MarketFrame` в том же модуле. Это единственное определение рынка для пунктов 3 и 5.

На дату `t` берут среднее `log_return` по тикерам, у которых доходность в этот день не NaN. День попадает в ряд только если таких тикеров не меньше `ceil(0.8 * N)`, где `N` — число включённых тикеров. Иначе дня в ряду нет.

Колонки: `time` (datetime), `market_return` (float), `n_names` (int).

### 5.4. Группа сектора

`sector_group` считается по включённым тикерам. Сектор с числом имён не меньше 5 сохраняет своё имя. Остальные имена получают группу `прочие`. Если в `прочие` меньше 5 имён, эти тикеры не участвуют в ящике по секторам, в Краскеле–Уоллисе и в секторных дамми регрессии. В таблицу метрик и в диаграмму «волатильность против размера» они входят.

## 6. Метрики инструмента

Считаются по непустым `log_return` тикера.

| Колонка | Формула |
| --- | --- |
| `n_returns` | Число непустых доходностей |
| `mean_log_return` | Среднее `r_t` |
| `ann_mean_return` | `mean_log_return * 252` |
| `ann_vol` | `std(r_t, ddof=1) * sqrt(252)` |
| `skewness` | Смещение выборочной асимметрии, `scipy.stats.skew` с `bias=False` |
| `excess_kurtosis` | Избыточный эксцесс, `scipy.stats.kurtosis` с `bias=False`, `fisher=True` |
| `median_turnover_rub` | Медиана `volume * lot * close` по барам с оборотом > 0 |
| `log_issue_size` | `ln(issue_size)` |
| `log_median_turnover` | `ln(median_turnover_rub)` |
| `age_years` | `(последняя дата свечи − ipo_date).days / 365.25`. Если год IPO меньше 1990, значение пустое (NaN), тикер из-за этого не исключается |

Проверки нормальности по каждому тикеру:

- Жарка–Бера по всем непустым `r_t`: статистика и p-value.
- Шапиро–Уилк, если `20 <= n_returns <= 5000`. Иначе статистика и p-value пустые, в колонке `shapiro_note` текст `skipped_n`.

Годовая волатильность при `n_returns < 2` не считается, такой тикер до таблицы метрик не доходит (его отсекает `min_bars`).

## 7. Зависимость от характеристик

### 7.1. Спирмен

Файл ранговых корреляций. Характеристики: `log_issue_size`, `log_median_turnover`, `log_lot` (`ln(lot)`), `age_years`, `div_yield_flag`, `short_enabled_flag`, `liquidity_flag`. Флаги кодируются как 0/1. Метрики: `ann_mean_return`, `ann_vol`, `skewness`, `excess_kurtosis`.

По каждой паре — коэффициент Спирмена, двусторонний p-value и `n` после попарного удаления пустых значений. Уровень 0,05 никуда не подстраивается по итогам прогона.

### 7.2. Секторы

Критерий Краскела–Уоллиса для `ann_vol` по `sector_group`. Запуск — если групп с размером не меньше 5 хотя бы две. Иначе в таблицу пишется одна строка с пустой статистикой и `note = too_few_groups`.

### 7.3. Регрессия

Обычный МНК, зависимая переменная `ann_vol`:

```text
ann_vol ~ log_issue_size + log_median_turnover + C(share_type) + C(sector_group)
```

База `share_type` — `common`. База сектора — `sector_group` с наибольшим числом имён. Стандартные ошибки HC3. В таблицу коэффициентов на каждой строке повторяются `base_sector`, `n` и `r_squared`.

Вторая оценка, отдельно от основной, добавляет `log_lot`, `age_years`, `div_yield_flag` и `short_enabled_flag`. Строки с пустым `age_years` из второй оценки выходят, первая оценка их сохраняет. Так видно, держится ли связь размера и оборота с волатильностью при расширении набора.

## 8. Модули

| Путь | Содержание |
| --- | --- |
| `tinvest/research/config.py` | `ResearchConfig`, чтение env |
| `tinvest/research/universe.py` | Загрузка карточек, фильтр, запись `universe.parquet` |
| `tinvest/research/panel.py` | `PanelFrame`, `load_panel`, `MarketFrame`, `equal_weight_market`, файл отброшенных доходностей |
| `tinvest/research/__main__.py` | Сбор выборки и запуск исследований. На этом пункте вызывается анализ распределения. Точка расширения для пунктов 2–5 — тот же `__main__`, без смены формата панели |
| `tinvest/analytics/distribution.py` | `DistributionConfig`, `DistributionSummary`, `ReturnDistribution` |
| `tinvest/client/candles.py` | Необязательный `figi` в `FetchConfig` |

`ReturnDistribution.prepare(panel)` присоединяет к панели каталог и считает метрики. `analyze` считает Спирмена, Краскела–Уоллиса и обе регрессии. `get_summary()` возвращает `DistributionSummary`: число включённых тикеров, медиана `ann_vol`, секторная группа с наибольшей медианой `ann_vol`, `r_squared` основной регрессии, доля тикеров с p-value Жарка–Бера ниже 0,05.

Бэкенд Matplotlib в `__main__` фиксируется как `Agg` до построения фигур.

Стандартизация для гистограммы: по каждому тикеру вычесть его среднее `r` и разделить на его `std(ddof=1)`, затем объединить. Поверх — плотность `N(0, 1)`. Это рисунок формы хвостов, а не разброса уровней волатильности.

QQ-сетка: 16 тикеров с наибольшим `median_turnover_rub`, теоретические квантили `N(0, 1)` против стандартизованных доходностей тикера. Если включённых тикеров меньше 16, сетка строится по всем.

На диаграмме размера цвет точки — `sector_group`, ось X — `log_issue_size`, ось Y — `ann_vol`.

В лог пишется строка со сводкой: число тикеров, медиана годовой волатильности, группа с наибольшей медианой, `R²` базовой регрессии.

## 10. Проверки без сети

Файл `tests/test_task1_panel.py`. Токен и сокет не используются.

- Три синтетических тикера по 300 торговых дней с известным нормальным шумом и фиксированным `seed`. Годовая волатильность из метрик совпадает с `std * sqrt(252)` с абсолютной погрешностью не хуже `1e-6`.
- Посаженный скачок цены в 2 раза даёт NaN в `log_return` и одну строку в `dropped_returns.csv`. Соседние доходности остаются конечными.
- При `max_names = 2` включены два тикера с большим медианным оборотом, третий имеет `exclude_reason = over_cap`.
- `equal_weight_market` не возвращает день, в который непустые доходности есть меньше чем у 80% включённых тикеров.
- Пустая панель в `prepare` приводит к `ValueError` с текстом, что выборка пуста.

## 11. Критерии приёмки

- `python -m tinvest.research` при заполненном токене создаёт `universe.parquet`, свечи включённых тикеров и пять таблиц плюс четыре рисунка этого пункта.
- У каждой включённой строки `included = true`, `share_type` входит в `{common, preferred}`, `n_returns >= min_bars - 1`.
- В метриках нет бесконечностей. Пустые значения допустимы только в `shapiro_*` при `skipped_n` и в `age_years` при раннем IPO.
- Основная регрессия содержит свободный член, `log_issue_size`, `log_median_turnover`, дамми `preferred` и дамми секторных групп кроме базовой.
- Повторный запуск с `refresh = false` не обращается к API за тикером, у которого parquet уже лежит на диске (в логе строка `Using existing candles`).
- Модульные проверки раздела 10 проходят.

## 12. Связь с другими пунктами

Пункты 2–5 берут `load_panel` и каталог этой задачи. Пункты 3 и 5 дополнительно берут `equal_weight_market`. Менять порог 0,5, смысл `log_return` и правило 80% покрытия в следующих пунктах нельзя: расхождение формулировок ломает сопоставимость результатов.
