# Задача 5. Прогноз повышенной волатильности

Пункт 5 плана из `README.md`: при достаточном объёме и качестве данных построить модель прогноза повышенной волатильности на заданном горизонте.

Панель, каталог и `equal_weight_market` берутся из `plans/task_1.md`. Аномальный оборот и пятидневная будущая волатильность — из формул `plans/task_2.md`. Признак `rv_21` считается так же, как в `plans/task_4.md`.

Модель отвечает на вопрос, выше ли реализованная волатильность следующих пяти торговых дней собственного высокого порога этой акции. Это классификатор состояния, не правило покупки или продажи.

## 1. Цель

На закрытии дня `t` оценить вероятность того, что годовая реализованная волатильность доходности на горизонте `t+1…t+5` окажется не ниже 80-го перцентиля собственных прошлых значений этой величины у того же тикера.

Сравнение идёт с двумя опорными оценками: постоянная вероятность, равная частоте класса на обучении, и сама уже наблюдаемая `rv_21` как числовой скор. Модель считается полезнее этих опор, только если на отложенных датах её ROC-AUC выше 0,5 и хотя бы на 0,02 выше ROC-AUC скора `rv_21`. Если порог не пройден, в сводке так и пишется: модель не улучшает опору на уже наблюдаемую волатильность. Прогон при этом успешный.

## 2. Общие соглашения

Окружение этого пункта: зависимости ставим и запускаем через uv. Перед командами активируем виртуальное окружение: `.venv/scripts/activate`.

Действуют соглашения пункта 1. Дополнительно нужны `scikit-learn`. `statsmodels` и `scipy` к этому пункту уже подключены предыдущими.

Запуск — `python -m tinvest.research`. Шаг выполняется последним. Если порог данных не пройден, файл `task5_skipped.txt` записывается, обучение не начинается, процесс завершается с кодом 0, результаты пунктов 1–4 остаются на месте.

Случайность: `random_state = 0` у бустинга и у перестановочной важности. Других источников случайности нет.

Масштабирование и список категорий сектора оцениваются только на обучающих датах.

## 3. Порог данных

Все условия проверяются до обучения. В `task5_skipped.txt` пишется каждое условие, фактическое значение и порог, в том числе выполненные. Если хотя бы одно не выполнено, файлов `task5_metrics.csv`, `task5_predictions.csv` и рисунков пункта нет.

| Проверка | Порог |
| --- | --- |
| Включённых тикеров | не меньше 40 |
| Дней в `MarketFrame` | не меньше 400 |
| Доля пустых `log_return` в панели включённых тикеров | не больше 0,05 |
| Медиана по тикерам числа валидных меток | не меньше 150 |
| Различных дат в тестовом отрезке | не меньше 60 |
| Оба класса есть в обучении и оба класса есть в тесте | да |

Доля пустых доходностей считается по ячейкам `log_return` панели после фильтра пункта 1, включая законные пустые значения первого бара. Порог 0,05 учитывает эти первые бары; при трёх годах истории они не выбирают исход проверки.

## 4. Метка

Горизонт `H = 5`.

```text
future_rv_5(t) = std(r_{t+1}, …, r_{t+5}, ddof=1) * sqrt(252)
```

Метка строится только если все пять доходностей непусты.

Порог тикера на дату `t` — 80-й перцентиль тех `future_rv_5(s)`, у которых `s + H < t` (вся будущая пятёрка `s` закончилась до `t`). Квантиль эмпирический, линейная интерполяция, как `numpy.quantile(..., 0.8)`. Если таких прошлых меток меньше 120, строка `(ticker, t)` в выборку модели не входит.

```text
y(t) = 1, если future_rv_5(t) >= порог, иначе 0
```

Порог использует только прошлое этого тикера. Метки тестовых дат, которые ещё не наступили относительно `t`, в порог не входят. Это же правило действует внутри тестового отрезка: для поздней тестовой даты прошлые тестовые метки, уже завершившиеся до неё, в порог входят, будущие — нет.

## 5. Признаки на закрытии дня t

Признак использует данные не позже `t`. Строка с любым пустым признаком удаляется.

| Колонка | Определение |
| --- | --- |
| `rv_5` | Как в пункте 2: годовой `std` пяти доходностей `t-4…t`, иначе NaN |
| `rv_21` | Годовой `std` 21 доходности, окно кончается в `t`, нужно 21 непустое значение |
| `rv_63` | То же для 63 доходностей |
| `log_return` | `r_t` |
| `abs_return` | `\|r_t\|` |
| `abn_volume` | Как в пункте 2: `log_turnover` минус медиана 21 бара, `min_periods = 15` |
| `parkinson_21` | Корень из среднего по 21 дням величины `(ln(high/low))² / (4 ln 2)`, затем умножение на `sqrt(252)`. День с `high < low` в панель не проходит ещё на этапе пункта 1 |
| `range` | `(high - low) / close` |
| `sma_gap` | `close / SMA_21(close) - 1`, SMA по 21 закрытиям, заканчивающимся в `t` |
| `market_rv_21` | Годовой `std` ряда `market_return` по 21 последним дням, где значение рынка есть. Имя колонки отличается от 63-дневного `market_rv` пункта 3 |
| `sector_group` | Группа из пункта 1, категориальный признак |

Идентификатор тикера в признаки не входит: иначе модель запоминает имя вместо состояния. `sector_group` входит.

`future_rv_5` в признаках нет.

## 6. Разбиение по времени

Берутся уникальные даты, на которых есть хотя бы одна валидная строка, по возрастанию. Пусть их `D`. Дата разреза — элемент с индексом `floor(0.8 * D)` (индексация с нуля). Обучение — даты строго раньше разреза. Тест — даты от разреза включительно.

Случайное разбиение строк запрещено: соседние дни одного тикера попали бы в обе части.

`StandardScaler` для числовых признаков логистической регрессии обучается на обучающих строках. Категории `sector_group`, которых не было в обучении, на тесте дают нулевой вектор дамми (все нули, без столбца «прочие неизвестные», если такой категории не было в обучении).

## 7. Модели

| Код | Правило |
| --- | --- |
| `constant` | Вероятность равна доле `y = 1` на обучении, одно число на все тестовые строки |
| `rv_21` | Скор для ROC-AUC — сырое значение `rv_21`. Для Бриера вероятность получается монотонным отображением: логистическая регрессия с одним признаком `rv_21`, обученная на обучающем отрезке |
| `logit` | `LogisticRegression(class_weight="balanced", max_iter=500, random_state=0)` по числовым признакам после `StandardScaler` и дамми сектора |
| `hgb` | `HistGradientBoostingClassifier(max_depth=3, learning_rate=0.1, max_iter=200, random_state=0, class_weight="balanced")`. Сектор передаётся как категориальный канал, а не как уже развёрнутые дамми |

Класс `balanced` фиксируется заранее из-за доли положительного класса около 0,2 (порог — 80-й перцентиль, на тесте доля плавает, потому что порог расширяется со временем).

Метрики считаются только на тесте:

| Метрика | Определение |
| --- | --- |
| `roc_auc` | ROC-AUC по скору. У `constant` скор постоянный, AUC записывается как 0,5 |
| `average_precision` | Average precision по тому же скору |
| `brier` | Средний квадрат разности вероятности и `y` |
| `positive_rate_test` | Доля `y = 1` на тесте, одна и та же для всех строк метрик |

Вероятность `logit` и `hgb` — `predict_proba` класса 1.

Условие «лучше опор» из раздела 1 применяется к `roc_auc` модели `hgb` и отдельно к `logit`. В сводке два булева поля: `logit_beats_baseline`, `hgb_beats_baseline`.

Коэффициенты `logit` сохраняются в исходном масштабе после умножения на масштаб скейлера, то есть как изменение логарифма шансов на единицу нестандартизованного признака, чтобы таблицу можно было читать без обратного пересчёта. Для дамми сектора коэффициент остаётся коэффициентом при 0/1.

Важность `hgb`: перестановочная важность на тесте, 5 повторов, метрика `roc_auc`, `random_state = 0`. В таблицу идут среднее падение AUC и его стандартное отклонение по повторам.

Калибровочная кривая строится для `hgb` по 10 равным по ширине бинам вероятности, если положительных меток на тесте не меньше 30. Иначе файл рисунка калибровки не создаётся, а в сводке `calibration = skipped_few_positives`.

## 10. Проверки без сети

Файл `tests/test_task5_forecast.py`.

- Утечка горизонта. На синтетической панели перестановка доходностей после даты `t` не меняет вектор признаков строки `(ticker, t)` и меняет `future_rv_5(t)`, если перестановка задевает `t+1…t+5`.
- Порог метки. Для даты `t` в расчёт квантиля не попадает ни одна пятёрка, пересекающая `t` или лежащая правее.
- Разрез. Максимальная дата обучения строго меньше минимальной даты теста. Доля дат обучения равна `floor(0.8 * D) / D` с учётом целочисленного индекса.
- Скейлер. Среднее признака, поданного в логистическую регрессию, на обучающей части равно 0. Среднее того же признака на тесте после того же скейлера может быть отличным от 0; тест подменяет тестовые значения большой константой и проверяет, что скейлер не был переобучен на этой константе.
- Порог данных. Панель из 10 тикеров пишет `task5_skipped.txt`, не создаёт `task5_predictions.csv` и не вызывает `fit`.
- Постоянный скор. Если `y` независимо от признаков и положительный класс есть в обеих частях, флаг `hgb_beats_baseline` способен быть ложным. Проверка здесь узкая: функция сравнения возвращает false, когда AUC модели 0,55, AUC `rv_21` 0,54 и порог улучшения 0,02.

Полное обучение на синтетике в тест не входит, чтобы приёмка не зависела от сходимости бустинга на игрушечном шуме. Отдельно проверяется, что `VolatilityForecast.analyze` на панели, прошедшей порог минимальными размерами (40 тикеров, 400 дней, оба класса заданы конструкцией ряда), создаёт `task5_metrics.csv` с четырьмя кодами моделей. Этот тест тяжелее остальных и использует ту же фиксированную конструкцию ряда, а не поиск по гиперпараметрам.

## 11. Критерии приёмки

- При данных ниже порога раздела 3 команда `python -m tinvest.research` завершается с кодом 0, пункты 1–4 записаны, у пункта 5 есть `task5_skipped.txt` и `task5_gate.csv` и нет `task5_predictions.csv`.
- При пройденном пороге в метриках четыре модели, предсказания покрывают только даты теста, у каждой тестовой строки вероятность `p_logit` и `p_hgb` лежит в `(0, 1)`.
- В `task5_predictions.csv` нет дат раньше разреза.
- Ни один признак строки `t` не зависит от `r_{t+1}…r_{t+5}`. Это закреплено тестом перестановки.
- Сводка в логе содержит AUC четырёх моделей и оба флага сравнения с опорой.
- Если бустинг не превосходит `rv_21` на 0,02, флаг `hgb_beats_baseline` равен false и в логе есть фраза, что модель не улучшает опору на уже наблюдаемую волатильность.
- Гиперпараметры раздела 7 не читаются из переменных окружения и не подбираются сеткой на тесте.
